# База знаний бота администрации

Знания бота лежат в папке `faq/`: **один файл = одна карточка = один вопрос жителя**.
Имя файла — латиница, маленькими буквами, слова через дефис (`priem-grazhdan.md`).
Этот `README.md` — не карточка: поиск читает только `faq/*.md`.

## Формат карточки

    # <вопрос так, как его задал бы житель>

    ключевые слова: <через запятую: синонимы, варианты с «ё» и без>

    <только факты: адрес, часы, телефон, порядок действий>

    источник: <ссылка на adm-tavda.ru>
    источник: <вторая ссылка, если факты из разных мест>
    проверено: ГГГГ-ММ-ДД

Разбор строк — по ним будет ходить поиск в `src/kb.py`:

1. Строка `# ` — вопрос-заголовок: то, что житель увидит в ответе.
2. Строка `ключевые слова:` — слова для поиска. Регистр не важен (поиск приводит к нижнему),
   «ё» и «е» считаем взаимозаменяемыми — поэтому в список пишем оба варианта.
3. Текст до первой строки `источник:` — факты. Только факты: без «наверное», «примерно», «как правило».
4. Строки `источник:` — ссылки, их может быть несколько; читаем **все**.
5. Строка `проверено:` — дата последней сверки с сайтом-источником.

## Правила

1. Факт без источника не пишем. Источников может быть несколько.
2. Всё, что нашёл в картинке или PDF, переносим в текст: поиск читает только текст.
3. Динамику (отключения, предупреждения, погоду) не храним — устареет за день.
4. Меняешь факт — обновляешь дату в строке `проверено:`.
5. Персональных данных жителей в базе нет (152-ФЗ). ФИО должностных лиц — только из официальных
   публикаций adm-tavda.ru.
6. Базу правит человек. Модель в базу сама не пишет.
7. Факт из чужой зоны (врачи, полиция, суды, соцфонд) — только как «куда обратиться»,
   с честной формулировкой «это не наша услуга».
8. Нет факта в базе → бот отвечает «не знаю» и даёт контакты. Это норма поведения, а не сбой.
9. Одна карточка — одна тема, синонимы описывают формулировки жителя, а не подтемы

## Как добавить карточку

1. `code knowledge/faq/<имя>.md` — новый файл по формату выше.
2. Открыть источник, сверить **каждую цифру вместе с её подлежащим** (чему эта цифра относится).
3. Заполнить все строки `источник:` и строку `проверено:` сегодняшней датой.
4. `git status --short -uall` — файл виден как новый (`??`).
