# evals — набор вопросов для оценки ответов

Материал для **Шага 6** («Тестирование на людях», оценка качества LLM-приложения). Здесь лежит сам набор; прогонщик (скрипт) появится на Шаге 6.

## Что внутри

- `questions.yaml` — 18 канонических вопросов жителей (`questions`) и 5 вопросов, на которые бот обязан ответить отказом (`negatives`).
- Вопросы собраны из реальных разделов adm-tavda.ru (см. заметку проекта «Шаг 2 — Вопросы жителей»), у каждого указан источник и статус карточки базы знаний.

## Что считаем на прогоне

1. **Попадание в факты** — для вопросов со `status: ready` в ответе обязаны быть факты из `expect`.
2. **Честный отказ** — для `planned` и для всего блока `negatives` ожидается «в базе нет» + контакт администрации, а не выдуманный ответ.
3. **Выдуманные конкретики** — главный стоп-критерий: телефон, номер кабинета, срок или адрес, которых нет в базе знаний. Один такой ответ = красный прогон.
4. **Доля «не знаю»** — метрика наполненности базы. Сейчас ожидаемо высокая (готовы 6 карточек из 18), после Шага 2 должна падать.

## Как добавлять вопросы

- Формат — как в `questions.yaml`: `id`, `text`, `status`, `source`, при необходимости `card`, `expect`, `forbid`, `note`.
- Каждый вопрос — из реального обращения или раздела сайта, с источником. Придуманные вопросы в набор не берём.
- При изменении ответа бота (новая карточка, новый промпт, RAG) набор прогоняется целиком — это регресс-тест качества.
